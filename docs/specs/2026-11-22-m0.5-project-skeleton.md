## 背景與目標

讓工具鏈、品質閘門與 AI 工作規則在寫任何功能之前就定好，讓 M1 之後的每個 PR 都能直接套用 DEVELOPMENT.md §4 的 Q1–Q5。

1. 用 uv 建立可安裝的 `src/mediabot` 套件（src layout，build backend 為 `uv_build`）。
2. 設定 ruff、mypy、pytest，`uv run` 就能執行 Q1–Q3。
3. 實作 `scripts/check_forbidden.py`（Q4），並附測試。
4. GitHub Actions CI：PR 與 push 到 `main` 時跑 Q1–Q4（Ubuntu + Windows）；pip-audit（Q5）每週排程執行，PR 改到依賴時也執行。
5. 讓 `CLAUDE.md`、`.claude/settings.json`、`REVIEW.md` 與 PLAN 一致（DEVELOPMENT.md §9）。
6. 補上 `.env.example` 與 `README.md`。

## 非目標

- 不建立 `security/`、`downloader/` 等子套件（各自的里程碑才建立）。
- 不加入任何執行期依賴（`yt-dlp`、`pydantic` 等留到 M1）。
- 不寫 `config.py`；`.env.example` 只列變數名稱，供 M1 的 `config.py` 對照。
- 不處理 `deploy/`（M5）。

### `pyproject.toml` 重點

```toml
[project]
name = "mediabot"
requires-python = ">=3.12,<3.13"   # 開發機與 Mac mini 都是 3.12
dependencies = []                  # 執行期依賴從 M1 開始加入

[dependency-groups]
dev = ["pytest", "pytest-asyncio", "httpx", "ruff", "mypy", "pip-audit"]
# 版本由 uv add 決定並寫進 uv.lock；pyproject 只寫下限

[build-system]
requires = ["uv_build>=0.13.6,<0.14.0"]   # 已用 uv 0.13.6 的 `uv init --lib` 確認
build-backend = "uv_build"
```

- 不寫 `authors`（避免把 email 放進 repo）。
- ruff：`target-version = "py312"`、`line-length = 100`；規則 `E, F, W, I, B, UP, S, SIM, RUF`。其中 `S`（flake8-bandit）用來偵測 `shell=True` 等安全問題，可補強 Q4；在 `tests/` 中忽略 `S101`（assert）。
- mypy：**全專案 strict**（`strict = true`，`files = ["src", "scripts"]`），比 PLAN「至少 security/ 與 downloader/」更嚴格。理由：專案剛開始，全面 strict 的成本最低，也不必維護 per-module 的旗標清單。之後若遇到沒有型別資訊的第三方套件（例如 yt-dlp），再針對該套件加上 `ignore_missing_imports`。
- pytest：`testpaths = ["tests"]`、`asyncio_mode = "auto"`；註冊 `integration` marker，並預設以 `-m "not integration"` 排除。

### `scripts/check_forbidden.py`

- 用法：`python scripts/check_forbidden.py [路徑…]`，預設掃描 `src/`。只使用標準庫。
- 以 `ast` 解析每個 `.py` 檔，回報：
  | 代碼 | 條件 |
  |---|---|
  | `os-system` | 呼叫 `os.system`、`os.popen`、`os.exec*`、`os.spawn*`、`os.posix_spawn*`、`pty.spawn`，以及同樣經過 shell 的 `subprocess.getoutput`、`subprocess.getstatusoutput`、`asyncio.create_subprocess_shell`（實作時補上） |
  | `shell-true` | 任何呼叫帶有 `shell=True` 關鍵字參數 |
  | `subprocess-str` | `subprocess.*` 的第一個參數是字串常數、f-string，或含字串常數的 `+` / `%` 運算、`str.format()`（應使用參數陣列） |
  | `eval-exec` | 呼叫內建函式 `eval`、`exec` |
  | `ytdlp-key` | 字典常數的鍵、常數下標（`opts["exec"]`），或關鍵字參數名稱，屬於 `exec`、`exec_before_download`、`cookiesfrombrowser`、`cookiefile`、`external_downloader`、`external_downloader_args`、`exec_cmd`；以及 postprocessor 字典中 `'key'` 為 `'Exec'` 或 `'ExecAfterDownload'`（yt-dlp 的 `--exec` 在 Python API 中的形式，review 後補上） |
- 輸出 `path:line: code message`；有發現時 exit 1，沒有發現時 exit 0，語法錯誤時 exit 2。
- 不支援 `# noqa` 一類的忽略註解：需要例外時，必須先修改本規格並取得擁有者同意。
- 讀檔使用 `utf-8-sig`（容許 BOM）；讀檔失敗（`OSError`）與語法錯誤一律 exit 2，優先於 exit 1。
- 相對匯入的名稱（`from . import subprocess`）不視為標準庫模組。
- 已知限制（由 review 把關，並寫在模組說明與 `architecture.md`）：動態組成的鍵（`opts["ex" + "ec"]`）、`getattr(os, "system")`、`__import__("os")`、先存進變數的指令字串、`**{"shell": True}` 展開。

### CI（`.github/workflows/ci.yml`）

- 觸發條件：`pull_request`、`push` 到 `main`、`workflow_dispatch`。
- job `checks`（matrix：`ubuntu-latest`、`windows-latest`）：checkout → setup-uv → `uv sync --frozen` → Q1 → Q2 → Q3 → Q4。

- `permissions: contents: read`；不使用任何 secret。
- action 版本：`actions/checkout@v6`（與現有 workflow 一致）；`astral-sh/setup-uv` 的主版本在實作時查官方 README 後固定。

## 風險與待確認

- `uv.lock` 由 Windows 產生，Ubuntu 與 macOS 能否直接使用？uv 的 lockfile 是跨平台的通用解析結果，預期沒有問題；CI 的 `--frozen` 會驗證這一點。
- ruff 的 `S` 規則可能對測試樣本中刻意寫的違規程式碼報錯 → 測試樣本以字串形式寫在測試中，交給 `check_forbidden` 解析，不放成真正的 `.py` 檔。
- GitHub Actions 必須在 repo 設定中啟用；Windows runner 會消耗 2 倍額度（已確認可以接受）。
